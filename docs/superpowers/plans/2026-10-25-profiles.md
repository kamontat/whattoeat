# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several fully separate restaurant worlds ("profiles") on one device, switched from
a new `/settings/profiles` page, with the active one shown in the Settings tab, and an export
format (version 8) that carries the applied-preset record.

**Architecture:** A new `src/lib/profiles.ts` owns the profile list, the active id and the one
function that turns a store name into a per-profile storage key. Every per-profile store
(`store`, `history`, `groups`, `filter`, `random`, `presets`, `tags`) swaps its fixed key
constant for that function. Switching only happens on the profiles page; every other page
reads the active profile when it loads, and `app-header` reloads any open page whose profile
was switched in another tab, so no store needs to know about switching.

**Tech Stack:** TypeScript, Lit 3, Bun (test runner with happy-dom), Biome.

**Spec:** `docs/superpowers/specs/2026-10-25-profiles-design.md` (the "Profiles" part and its
"Export, import and reset" section). The "Presets" part is a separate plan and PR.

## Global Constraints

- Shared across profiles: `whattoeat:lang` and `whattoeat:theme` only. Everything else in the spec's "What a profile holds" list is per profile.
- `whattoeat:profiles` holds `{ id, name }[]` in creation order; `whattoeat:profile` holds the active id.
- Profile names: required, trimmed, unique case-insensitively, at most 24 characters.
- Default profile name: "Personal" in English, "ส่วนตัว" in Thai, chosen by the language active at creation, never re-translated.
- There is always at least one profile; the last one cannot be deleted.
- A new profile starts empty: no restaurants, no custom tag groups, no history, default filters and pick count.
- Export format version goes from 7 to 8, adding `presets: { id, updatedAt, ids }[]`.
- Build with the existing design system (`src/styles/`, `uiStyles`, the `.group`, `.item`, `.lead`, `.grow`, `.trail`, `.actions`, `.danger`, `.primary` patterns), not the brainstorm prototype's styling.
- Every change follows `shipping-a-change`: worktree (already `worktree-profiles`), test first, `bun run format && bun run check && bun run test && bun run build` before each commit.
- Conventional lower-case commits scoped by area (`feat(lib): ...`, `feat(components): ...`). No `CHANGELOG.md` edit until landing.

## Review Focus

1. **Storage blocked (private mode, quota).** The app still opens with one default profile held in memory, and the profiles page still lists it. Test in Task 1.
2. **Upgrade keeps every byte of existing data.** Restaurants, history, groups, both filters, pick count and preset record all appear under the new "Personal" profile, the old keys are gone, and a second load does not run the upgrade again. Test in Task 1.
3. **Two tabs open, profile switched in one.** The other tab reloads instead of writing the old profile's data. Test in Task 6.
4. **Deleting a profile leaves nothing behind.** Every `whattoeat:<id>:*` key of the deleted profile is removed; other profiles' keys and `lang`/`theme` stay. Test in Task 1.
5. **Names that are awkward to abbreviate.** The avatar initial of an emoji or Thai name is its first whole character (`Array.from(name)[0]`), not half a surrogate pair. Test in Task 1.
